# 与你相恋

给 N.E.K.O 角色加一层恋爱关系：好感度 0–100，五个阶段（陌生 → 熟悉 → 好感 → 暧昧 → 恋人）。
角色在文字聊天里按阶段调整语气和分寸；每轮对话后插件自动判断好感变化，好感会下降，阶段也能倒退。

- 默认用本地关键词判断，无需设置；在 N.E.K.O 的「Plugin API」页给「好感判断」绑定一个模型可以判断得更准。
- 自动判断每轮最多 ±3；每天聊天最多 +4、送礼最多 +4，单份关系合计最多 +8 / -4。
- 吐槽工作、心情不好不算冲着角色；每天第一次扣分减半。
- 好感到 80 后需要在聊天里真的告白才成为恋人（可关闭）。角色可以根据对话语境确认双方心意并记录关系，不要求固定告白句式，也无需另外绑定判断模型。
- 可选：开启「允许猫娘主动告白」，角色达到条件后在正常聊天后主动表达心意，等你明确答应；有冷却与次数限制，默认关闭。
- 可选：好久没聊时好感慢慢变淡，但不会让关系倒退（默认关闭）。
- 面板可以看 30 / 90 / 365 天的好感走势。
- 默认所有角色共用一份好感；可在面板里开启「每个角色独立好感」，切换不会清除任何数据。
- 你说话时插件会悄悄把当前关系告诉角色（不打断对话）。
- 每阶段可选默认、自定义、沿用人设或继承。默认保留人设和用户认可的名字，确认恋爱后才允许偶尔使用「亲爱的」，不会强制切换成宝宝或婚姻称谓。
- 可设置偏好名字、不接受的称呼和通用甜称开关；称呼页显示每阶段的生效结果与来源。用户在聊天里明确纠正称呼时，角色可调用工具保存偏好，不改变关系。
- 已确认的恋爱关系不会因好感降低自动消失；角色提示和概览区分关系事实与近期亲近程度。
- 「清零好感」保留已有恋爱关系；「重新开始关系」经确认后回到陌生，清除恋爱确认和在一起日期，保留历史、相识日、偏好和资产。
- 已有共用称呼和各角色独立称呼分别保留，切换好感模式不会互相覆盖。保存只更新修改过的阶段，同一阶段发生冲突时保留草稿并提示处理。
- 自动记录相识日和在一起的日子，第 100 / 520 / 1000 天和每个周年角色会记得；也可以添加生日等自定义纪念日。
- 在「纪念日 → 我们的日子」可从宿主历史查询相识日，预览后确认导入；共用模式查询所有角色，独立模式只查询所选角色。
- 「修改相识日」可选择插件原始日期、上次导入的宿主日期或自定义日期；原始日期与导入日期分别保留，重启后仍可切换，无需重新查询宿主。
- 共用立绘库支持固定图片、随机展示和关闭，可浏览缩略图并选择随机范围。
- 礼物商店：日常聊天达标后手动领取金币，购买六种礼物，选择角色送礼，猫娘通过宿主聊天模型回应。
- 使用说明见插件内的「使用指南」页（`docs/guide.md`）。
- 可选的「共同经历」：按参与角色一起写便签、约好以后关心一件事。草稿与正式留存分开，预览确认后才成为回忆；支持修改、删除、停止引用和延后关心，不额外加好感或发金币。默认关闭。

### 同行 YUI 外观（0.8.6）

素材由 AI 先生成三视图和分件图，再按骨骼拼装、合成动作帧。帧按游戏中的显示尺寸绘制，不再二次缩放，人物比上一版更大、更清晰。同行者在世界坐标中的碰撞体与原来相同，战斗规则、存档与随机数不变。素材加载失败时回退为矢量小人并显示提示。玩家形象与其他猫娘暂未更换。设计与制作记录见 `docs/adventure-portrait-design-2026-11-14.md`。

### 双角色技能构筑（0.7.8）

新冒险使用独立的双方技能路线：玩家选择火术或突击剑，同行选择引风术或守护剑。共享经验，每三次成长依次分配给玩家、玩家、同行；团队最高 31 级。升级可学招、选择威力或节律、选择互斥分支、精研和进化。首批八个技能；玩家持续自动攻击，Q / E 释放已学的主动技能，触屏提供技能按钮。

同行将引风或岩甲升到 3 级并选择接续分支后，可以响应玩家的焰环或突进。接续消耗同行自己的冷却，同一次主动施法只接续一次；同行也保留自主作战。技能图鉴展示分支及复合进化条件，读档保留技能、冷却、待选项与两次共用重选的剩余次数。

进行中的旧冒险仍按原战斗规则继续。冒险文件升级至 v3，首次写入前备份有效的 v1 / v2 文件；钱包、属性商店与结算方式沿用 0.7.7。实际实现与验证范围见 `docs/adventure-skills-2026-11-12.md`。四元素、更多剑术、完整小首领节奏与归来共创属于后续扩充；本版没有将全部设计目录一次实现。

### 模块职责与界面状态修订（0.7.5）

### 聊天来源、事件状态与启停恢复（0.7.4）

统一排除带有明确特殊来源标记的消息，修复总线与兼容历史并发读取同一轮的问题；启动前说过、启动后才转发的用户消息不补算。总线按原始全文指纹去重，避免相同前缀、标点差异或长消息末尾差异被合并。

送礼只有明确拒收才使用较短重试等待，回执不明确时保持「暂未确认」。邀请丢失响应后沿用原请求核对，返回当前已保存的邀请状态，不再次邀请。主动告白使用每次请求独立的关联标记，需要对应事件或指令与回复配对的证据；角色相同、文本像告白均不能单独证明来自本次请求。结果不确定的告白请求保留已占用的尝试次数，重启不再释放次数。

启动过程与停用互相核验代次，并排空已接纳的启动文件操作；重复启动会被拒绝。重载刷新工具绑定、消息来源与提示缓存，旧查询工具和迟到邀请不能继续操作新会话。保留原有存档格式，补充旧版升级、原子保存失败后恢复与重复请求测试。完整记录见 `docs/conversation-lifecycle-audit-2026-11-12.md`。

### 解耦、性能与安全修订（0.7.3）

面板快照与展示计算移到独立纯模块，只复制当前需要展示的关系与历史；金币进度和共同经历等单域操作只备份自身状态，跨关系、背包和金币的赠送仍整体回滚。立绘与外观读写使用独立锁，减少对关系操作的阻塞；固定立绘选择复用本次文件检查，不缓存失效的文件状态。

本机 HTTP 请求禁用重定向，JSON 响应最多读取 8 MiB；存档最多读取或写入 32 MiB，拒绝重复键、非有限数值和过深 JSON。异常存档隔离保留并停止启动；无效保存不替换原文件。补齐面板停用后的写入检查，已接纳的素材操作在停用完成前排空。评分模型的 30 秒超时覆盖获取客户端和请求两个阶段，评分提示只保留一份结构化对话数据。

合成基准中，64 角色共用关系的面板生成中位耗时由 33.265 ms 降至 4.787 ms，金币进度更新（包含原子写盘）由 42.177 ms 降至 23.758 ms；这不是实机整体响应时间。792 项 Python 测试、109 项界面与主题测试通过。完整审查、测量方法和验证边界见 `docs/decoupling-performance-security-audit-2026-11-12.md`。

### 稳定性修订（0.7.2）

本轮在现有玩法上修复保存、恢复与启停边界，不修改宿主。便签「只更新草稿」同时保存标题与正文；损坏文件的隔离备份使用唯一文件名，短时间内多次出错不会覆盖上一份。未知的关系或经济存档版本、JSON `null` 及结构损坏的角色记录会停止启动并保留原文件，避免默认值覆盖已有关系与钱包；已支持的旧版本仍按原流程备份迁移。

关心提示先保存一次性发送标记，再调用宿主队列。保存失败不发送；明确拒收可重试，提交结果不确定或中途退出不自动重发。极端情况下可能少提示一次，可在面板修改或延后后重新安排；标记只表示已安排，不能证明角色实际收到或提问。便签邀请也只有明确的 `submitted=true` 才显示已提交。

插件停用后，迟到的角色同步、工具核对、聊天读取与关系查询不再继续写入、注册工具或发送提示。旧一次启动的异步结果即使在重启后返回，也不会应用到新会话。审查范围、复现用例与验证边界见 `docs/stability-audit-2026-11-12.md`。

### 首页与导航（0.7.1）

导航按「日常相处」和「关系记录」分组，共同经历紧随关系概览，设置放在底部。宽窗口首次默认显示文字标签，手动收起后保留当前面板的选择；窄窗口仍使用图标导航。

### 共同经历（0.7.0）

新增「共同经历」页，包含「一起写便签」和「以后关心」两个原型。首次开启前说明本机内容保存范围；与好感共用开关无关，每份内容始终归实际参与角色。

写便签时先选角色，输入标题与自己的第一句，保存创作草稿；点击「邀请一起写」请求角色在宿主聊天中参与。角色可以通过本角色的工具更新草稿。回到面板预览、编辑，选择「确认留存」才成为可回忆的便签；也可只更新草稿或结束创作。邀请提交不代表回应已生成，暂无法确认时不自动重发，手动重试至少间隔两分钟。

关心事项可在面板提出，或在聊天中明确同意后由角色工具整理为待确认草稿。预览摘要和具体日期，点击「确认约定」后生效。到期后等你下一次正常聊天提交一次被动关心提示，不在空闲时主动打扰，不补发旧聊天；提示提交不保证模型实际提问。可以修改或延后、记录自己报告的结果、选择不再跟进或删除。角色提出的结果仍需你确认，不自动推断现实结果。

默认只向角色提供最近两条允许回忆的便签，每条最多 240 字，不提供关闭引用的便签。每个角色最多留存 30 张便签、20 条关心事项，共同经历数据总量上限为 768 KiB；达到上限后由玩家选择删除，不自动清理。共同经历随 `state.json` 原子保存；重启保留，待确认邀请不自动重发，重试复用原请求。关闭保存后停止后续注入，已有记录仍可查看和删除。删除不能清除已经进入宿主历史的文字。

「重新开始关系」取消相应参与角色的创作和跟进，历史便签保留但自动关闭引用；共用关系重新开始影响全部参与角色，独立关系只影响对应角色。「清零好感」不清除共同经历。机制不依赖额外判断模型，但聊天共创依赖宿主角色模型调用工具的能力；面板可以直接编辑确认作为兜底。

### 隐私

默认只在内存里读取最近的聊天内容来判断好感，不把完整聊天写进文件。本机插件数据目录保存好感数值、每天的好感、每次变化的一句理由、告白时的一句记录、主动告白的状态与时间和次数、你设置的称呼和纪念日，以及单独存放的立绘和外观偏好。商店保存余额、背包、日周互动进度、有限消息摘要指纹与来源额度、最近 100 条收支流水、50 条赠送记录及 64 笔交易回执；不保存猫娘的送礼回复原文。主动开启「共同经历」后，另保存编辑中的便签、待确认事项和结果草稿，以及你确认留存的内容；可以查看、编辑、删除或停止后续引用。

没有绑定判断模型时，好感评分不访问外网。插件读取本机 N.E.K.O 主程序的角色列表、工具列表和对话总线；旧版宿主没有普通聊天总线时，兼容读取宿主本机近期聊天接口，仅处理启动后新观察到的对话。手动查询相识日时，也通过本机接口读取保留的聊天记录，仅在内存中提取日期，不保存、记录或上传聊天原文，不调用模型。绑定后，每一轮和上一轮的对话（每句最多 300 字）会经 N.E.K.O 发给你在「Plugin API」里配置的模型。

0.6.1 按发布前测试阶段的决定统一称呼默认值：已有存档首次启用此版本时，共用和所有独立角色的五阶段都改为「阶段默认」，偏好名字和禁用词清空，恋人通用甜称开启。复位前保存整份 `state.pre-addressing-defaults-v1.json`，失败则停止启动；关系、好感、历史、日期和商店数据保留。`addressing_defaults_version=1` 保证只执行一次，后续重启保留用户修改。全新安装直接使用相同默认。

「专属称呼」页提供「恢复全部默认」，点击即保存当前选中关系的全部称呼默认设置，其他角色不受影响；每阶段的恢复按钮仍只修改该阶段草稿。回退方法及备份范围见使用指南的「称呼」章节。

称呼默认是可修改的设计候选，尚未经目标用户舒适度实验验证；并非研究证明最受欢迎的词表。研究、体系审查与后续验证计划见 `docs/relationship-addressing-plan-2026-11-11.md`。配置保存和提示提交不能保证聊天模型每次准确执行，实机聊天仍需验证。

### 礼物商店

首次启用获得 100 金币。每天第 1、3、8 轮合格互动各解锁 10 金币；本地周一到周日中，有四天完成至少三轮合格互动，解锁周奖励 40 金币，不要求连续。达标后在商店分别点击领取才会入账，完整参与并领取一周最多获得 250 金币。关闭面板或自动好感评分仍记录进度；打开商店和挂机不发币。日奖励最迟次日领取，周奖励最迟下一周领取，商店显示待补领入口。余额与背包所有角色共用，送礼时单独选择对象，不涉及充值。

商店提供红茶、蛋糕、巧克力、花束、故事集和玩偶，价格 20–80 币，好感最多增加 1–4 点。每天送礼全角色合计最多 +4，与每份关系聊天的 +4 分别计算，单份关系合计最多 +8。实际加分受剩余额度与好感上限限制，确认窗口显示具体结果；状态变化需要重新确认，送礼不会绕过告白。

好感已满或额度用完时，普通赠送不消费；可以主动选择「仅表达心意」，明确以 +0 好感消耗一份礼物并请求回应，所有角色每天限一次。「收支记录」显示奖励和购买的金额及当时余额。奖励不要求连续签到，已有钱和库存不过期。

购买进入背包，赠送时扣除一件并记录实际好感变化。余额、库存、好感和交易回执一起原子保存，超时后「确认上次操作」沿用原交易，不会重复扣币或送礼；旧面板需先刷新再操作。

猫娘的回应出现在宿主聊天中。赠送记录会区分已请求、已确认回应和无法确认；提交成功只表示本地请求已接收。回应暂不可用时稍后可单独重试，不再扣礼物或增加好感；最多请求三次，提交失败后至少等待 30 秒，已提交但未确认时等待 120 秒。宿主某些通道缺少关联回执时会保留“暂未确认”，不会用其他聊天冒充送礼回应。重启后不自动重发不确定的请求。

实现与维护说明见 `docs/gifts.md`。

升级保留余额、背包和好感，并备份旧存档。当天领过旧签到奖励的不重复发日奖励；当天旧加分来源不明时，新的好感额度次日启用。存档损坏会隔离备份并停止启动，需恢复状态后重启，不自动生成新钱包。

### 装饰立绘

在「设置 → 立绘」选择固定、随机或关闭。图库及偏好所有角色共用，与独立好感开关无关。

- 固定模式：浏览图集、搜索名称、选择一张图片；选择会保存，重启后仍生效。
- 随机模式：每次打开面板抽取一张；切页、切角色和刷新数据不换图。可手动「换一张」，有多张候选时避免紧接着重复，也会避开上次打开面板时的最后一张。
- 随机范围：可跨页勾选任意图片，「全部加入」包含以后新增的图片，「清空选择」保持空范围，不会自动变回全部。
- 关闭：不显示立绘，正文使用全部可用宽度。

内置图库共 8 个游戏、64 张立绘：原有《千恋万花》18 张，加上用户提供的「精选立绘_Key与Qruppo」中筛选保留的 46 张。已移除《ぬきたし》的全部素材及《天使嚣嚣》的部分泳装、内衣款式，整理工具通过 `tools/portrait_exclusions.json` 防止重新加入。选择立绘时按游戏筛选，也可选择全部游戏并搜索名称。保留图片的 ID 不变；被移除的固定图片会回退到可用图片，随机范围会忽略已移除条目。展示图和缩略图放在 `assets/portraits/`，通过 `catalog.json` 管理；不复制原始大图。运行时仅按需读取本地图片。

面板中的「导入立绘」支持批量选择 PNG、JPEG、WebP，先预览、修改名称，选择已有游戏或新建分类，再确认导入。每批最多 24 张，单张原图最多 32 MiB、4000 万像素；面板自动裁去透明空白、保留透明背景并生成展示图和缩略图。相同处理结果会复用已有立绘，不重复占用图库；部分失败可重试，已完成的条目不重复提交。自定义立绘旁的编辑按钮可以改名、移动游戏分类和删除；删除需要再次确认，并同步移出固定选择和随机范围。

导入图片单独保存在 SDK 分配的插件数据目录 `custom_portraits/`，名称、分类及显示偏好在 `portraits.json` 中原子保存。重启保留，替换插件代码或内置素材不会覆盖用户导入的图片；不保存原始大图。普通运行不依赖 Pillow。

开发时新增内置图库：安装开发工具 Pillow 后运行 `python tools/prepare_portraits.py "素材目录" --merge --grouped`，其中每个一级子目录作为游戏分类；单个游戏目录使用 `--collection "游戏名"`。`--merge` 保留已有图库，不指定则重建；同一来源相对路径保持相同 ID。可用 `--output` 指定输出目录。清单格式见 `assets/README.md`。整理工具不进入插件包。

旧版 `assets/decoration.webp` 和 `assets/stage_<阶段>.webp` 仍可在「旧版阶段图」模式使用；阶段为 `stranger` / `familiar` / `fond` / `ambiguous` / `lover`，缺少阶段图时回退默认图。也支持 PNG、JPG、JPEG、GIF，每张不超过 1 MiB。新图库不会按宿主角色或好感阶段自动切换。

面板分为「关系概览 / 心动记录 / 纪念日 / 专属称呼 / 礼物商店 / 设置 / 共同经历」七页。桌面侧栏可收起为 56px 的图标导航，仍可直接切页；700px 以下窗口自动使用图标导航，鼠标悬停显示页面名称。数据刷新保留当前页面、侧栏和所选角色。

立绘在关系概览展示，设置页显示小图预览，其他页面让正文使用全部宽度。立绘留在概览顶部，随正文滚出视野，不跟随滚动覆盖下方信息。立绘栏最大宽 220px、高 360px，随面板宽度平缓缩放；480px 及以下移到标题右侧，为关系信息保留完整宽度。支持深浅色主题和减少动态效果偏好。

侧栏、正文和弹窗统一使用细滚动条，隐藏轨道及两端箭头。鼠标靠近滚动区域右边缘或正在滚动时显示滑块，离开且停止操作约 1 秒后淡出，悬停或拖动时加深。滚动条保留固定宽度，显隐不挤动正文；短窗口自动压缩导航间距，侧栏不再横向滚动。键盘聚焦区域时显示滚动提示，正文可用 Page Up / Page Down 翻页；触屏和系统高对比度模式保留可见提示，减少动态效果模式不执行淡入淡出。

称呼草稿按角色临时保留，切页、切角色和后台刷新不会覆盖未保存的修改；可保存或撤销，关闭面板后未保存草稿会丢弃。好感调整支持数字输入和滑块，相识日输入限制为 1970 年至今天。保存过程中禁止重复提交和关闭弹窗；保存成功后若刷新失败，会单独提示刷新，不重复执行保存。

相识日可手动修改，也可点击「从宿主历史导入」：先查看当前日期、候选日期及来源角色，再确认替换。查询和取消不修改日期；查询后如果日期被其他操作修改，会提示重新查询。候选仅代表宿主当前可读取的普通聊天中最早的日期，识别消息时间元数据，也兼容紧随用户发言的旧版宿主带日期回复；更早记录可能已被清理，无法据此确定下载或安装日期，也不是累计在线时长。

「修改相识日」保留插件原始日期、上次确认导入的宿主日期和上次保存的自定义日期，选择后点击保存即可来回切换。仅预览、不确认的宿主日期不会保存；没有导入过时，宿主日期选项不可用。日期选择按共用与各角色独立关系分别保存，模式切换不会覆盖已有关系的日期设置。旧版没有单独保存原始日期，会保留升级时的相识日作为恢复点，界面标注「升级前的相识日」；升级前已经被覆盖的更早日期无法保证还原。

概览显示最近一次心动记录，可直接进入完整记录。设置页提供固定在顶部的分区入口，较长的规则说明可展开查看。称呼显示已用字数，称呼与纪念日名称的长度按 Unicode 字符计算，避免截断 emoji。

导航、按钮、主题色、开关和图库选择提供统一的悬停、按压与释放反馈，不改变控件位置和尺寸；触屏不保留鼠标悬停效果，键盘操作与减少动态效果偏好也有对应反馈。请求发出后，触发控件标记忙碌状态，处理中与实际成功分开呈现。

成功反馈按文字长度在 6 至 12 秒后自动收起，鼠标悬停、键盘聚焦提示或页面进入后台时暂停计时；错误、警告和处理中提示持续保留。弹窗内的失败提示保留在操作按钮旁，输入不会丢失。保存后刷新失败时明确区分已完成的保存与尚未更新的显示，提供单独刷新入口。

本轮审查记录见 `docs/ui-review-2026-11-07.md`。

### 主题配色

默认配色为晴空蓝。在「设置 → 外观」选择樱粉、晴空蓝、薄荷绿、雾紫、杏桃或湖水青，也可以用取色器自选颜色，或输入 `#RRGGBB` 色号。选择后立即预览，点击「保存」后生效到后续打开的面板；未保存时可撤销，也可恢复默认晴空蓝。

显示模式支持跟随系统、浅色和深色。文字、按钮和图表按所选颜色自动生成可读的深浅变化。设置对所有角色共用，保存在插件数据目录的 `appearance.json`；重启保留，不修改宿主主题。切页或切角色不会丢掉正在预览的配色，关闭面板会丢弃未保存修改。

### 本地开发（不改动宿主）

1. 在本目录运行 `python -B tools/prepare_development.py`（Python 3.11 或以上），在仓库旁生成 `../.neko-dev/love_with_you`。也可以使用宿主已有的 Python：`& "../N.E.K.O/.venv/Scripts/python.exe" -B tools/prepare_development.py`（PowerShell）。
2. 在 N.E.K.O 插件管理器左侧打开「开发模式」，点「加载未打包插件」，选择脚本输出的 `.neko-dev/love_with_you` 绝对路径。宿主要求加载目录名与入口包名一致，不能直接选择带点号的仓库目录。
3. 继续在当前源码目录修改文件；修改后重新运行准备脚本，再点开发插件卡片上的「重载」。生成目录是可重复生成的副本，不要在那里编辑；脚本不会改动宿主或插件数据目录。
4. 测试：在本插件目录使用已安装 pytest 的 Python 运行 `python -B -m pytest tests --rootdir=tests --confcutdir=tests --import-mode=importlib -p no:cacheprovider --basetemp "../.pytest-love-with-you"`。
   （`--basetemp` 防止 pytest 在本机临时目录不可写时把临时文件写进插件或宿主目录。）
   测试无需启动宿主或绑定模型；运行时测试会隔离 SDK 边界，并实际验证评分线程、过期结果丢弃和停止/重启行为。
