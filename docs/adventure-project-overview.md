## 1. 项目是什么

- **宿主**：N.E.K.O，一个桌面角色程序。**宿主代码不能改**，这是项目主人的硬性要求。
- **插件**：`n.e.k.o_plugin_love_with_you`（入口包名 `love_with_you`，中文名「与你相恋」），给宿主角色加恋爱关系。
- **游戏**：插件里的一个独立小游戏，俯视视角的双人幸存者类动作游戏。玩家操作「旅人」，宿主角色作为「同行」自动协助。世界观借用《无职转生》的魔术阶位、剑术流派等框架，**招式名、角色、怪物全部原创**。
- **项目主人**：用中文交流，不是程序员出身，玩法和关卡设计希望由开发者提出方案、他来试玩和拍板。

游戏与插件其余部分相互隔离：冒险有自己的存档文件和金币，不读写好感度、礼物金币，也不调用模型。

## 3. 运行与测试

### 试玩

双击 `play-adventure.bat`，浏览器打开 `http://127.0.0.1:4321`。预览用的是临时存档，不影响宿主里的真实进度。也可以手动运行：

```
python -B tools\preview\adventure_preview.py --port 4321
```

### 后端测试

在插件根目录：

```
python -B -m pytest tests --rootdir=tests --confcutdir=tests --import-mode=importlib -p no:cacheprovider
```

整理前已有 1129 项，应全部通过。运行约一分钟，耗时依机器而定。

### 前端测试

纯规则测试只需要 Node：

```
npm --prefix tools run test:rules
```

浏览器测试需要 Playwright 和一个 Chromium。环境变量：

| 变量 | 含义 | 不设时 |
| --- | --- | --- |
| `NEKO_PYTHON` | 运行预览服务器的 Python | 宿主目录下的 `.venv\Scripts\python.exe`，没有就用 PATH 里的 `python` |
| `NEKO_HOST_ROOT` | 宿主目录 | 插件旁边的 `N.E.K.O` 或 `N.E.K.O-main` |
| `NEKO_UI_DEPS` | 装有 `playwright` 的目录 | `tools\node_modules` |
| `NEKO_UI_BROWSER` | 浏览器可执行文件 | Playwright 自带的 Chromium |
| `NEKO_UI_ARTIFACTS` | 截图输出目录 | `archive\reviews\browser`；导航测试为 `archive\reviews\navigation` |

完整一轮（约 20 分钟，必须串行）：

```
node --test --test-concurrency=1 tools/tests/test_adventure.mjs tools/tests/test_adventure_protocol.mjs tools/tests/test_adventure_skills.mjs tools/tests/test_expanded_combat.mjs tools/tests/test_buildcraft.mjs tools/tests/test_encounter_rules.mjs tools/tests/test_journey_rules.mjs tools/tests/test_mastery.mjs
```

只跑一部分用 `--test-name-pattern="rule11"`。

### 平时跑多少测试

项目主人不想每次改动都等完整的一轮。日常做法：

- 每次改动后跑后端测试（当前约一分钟）和 Node 纯规则测试（几秒）。
- 浏览器测试只跑和改动直接相关的用例，用 `--test-name-pattern`。
- 完整的一轮留到加新规则版本、动了公共模块（`adventure.mjs`、`combat.mjs`、`skills.mjs`、`bridge.mjs`、后端校验）之后，并且有空的时候再跑。跑没跑、跑到哪，在汇报里说清楚。

## 4. 架构

### 一局游戏的数据流

1. 前端 `adventure.mjs` 里的 Phaser 场景运行战斗。
2. 每隔一段时间、每次升级选择、每次选门时，场景生成一个**快照**（完整的可恢复状态），通过 `bridge.mjs` 发给后端。
3. 后端 `backend/adventure/service.py` 用**严格校验**检查快照：字段必须完全匹配，数值必须在范围内，状态之间必须自洽（比如拥有的弹体必须对应学过的技能）。不通过就拒绝保存。
4. 结算（金币）只由后端按快照计算，前端只显示。

所以：**前端加任何进快照的东西，后端校验和测试必须同时改**，否则存档会被拒绝。

## 5. 规则版本

这是项目里最重要、也最容易出错的机制。

每一局开始时记下当时的**战斗规则版本**（`rules`），这一局从头到尾按这个版本的规则运行和校验。这样更新游戏之后，玩家打到一半的旧旅程不会坏。代码里到处是 `rules >= N` 的判断，就是为了这个。

| 规则 | 版本 | 加了什么 |
| --- | --- | --- |
| 1–3 | 0.7.7–0.8.0 | 原型、双角色技能、精研与冰系 |
| 4 | 0.8.1 | 守关强敌、首领、双人协同 |
| 5 | 0.8.3 | 固定的林地布局与地形碰撞 |
| 6 | 0.8.4 | 流派与扩展技能 |
| 7 | 0.8.5 | 局内自由构筑 |
| 8 | 0.9.0 | 九段旅程、小场地、选门、按段结算 |
| 9 | 0.9.1 | 终结技；首领生命 ×1.6；每段战斗后回复 10% |
| 10 | 0.10.0 | 火系精通与流派共鸣 |
| 11 | 0.11.0–0.11.1 | 火系技能线、等级上限 50、难度上调 |
| 12 | 0.12.0 | 精英词缀、守关强敌第二阶段与新招式、首领第三阶段、险路提前到第二段 |
| 13 | 0.9.2（步骤 0.9.1） | 火系手动技能线与一键连招；焰环精通由这条线取代 |
| 14 | 0.9.2（步骤 0.9.2） | 停靠点（篝火、行商、奇遇）与局内货币林晶 |
| 15 | 0.9.2（步骤 0.9.3） | 剑系自动线、剑意、剑系共鸣、按流派选择终结技（拔刀斩） |
| 16 | 0.9.2（步骤 0.9.5） | 地形机制：遗迹可碎石柱，深处荆棘减速与毒雾 |
| 17 | 0.9.2（步骤 0.9.6） | 走出口选路（暂停仍可用面板），首领圣所第三阶段根须封场 |
| 18 | 0.9.2（步骤 0.9.8） | 突进手动线（连斩／回身斩 → 八方斩／残影 → 剑域）与一键连招 |

存档文件另有自己的版本号（`backend/adventure/service.py` 的 `VERSION`，现在是 19），每加一个规则版本就加一。旧文件第一次被新版写入之前会自动备份。

### 什么时候要加新规则版本

- **要加**：改变了已有技能或敌人的数值、快照里多了字段、已有的合法状态变成不合法。
- **不用加**：纯表现改动；或者只是在数据目录里**新增**选项，旧存档在新校验下仍然合法。0.11.1 加狱炎弹和瞬燃就没有加版本。

### 加一个规则版本要改的地方

1. `backend/adventure/service.py`：`VERSION`、`RULES`、三处允许的规则列表、迁移时允许的旧版本列表。
2. `backend/adventure/skills.py`：`CATALOGS[N]`，以及新字段的校验。
3. `static/bridge.mjs`：两处允许的规则列表。
4. 前端：新行为放在 `rules >= N` 后面；`skills.mjs` 的 `buildRules` 和 `newBuild` 如果构筑多了字段也要改。
5. `tests/test_adventure.py`：版本断言、一条“旧版文件迁移并备份”的测试、新字段的正反例。
6. `tools/tests/test_adventure_protocol.mjs`：未知规则版本的那个循环。
7. `tools/tests/test_adventure.mjs`：新开局默认规则的断言；依赖旧规则行为的用例用 `harness({ displayRules: N })` 固定在旧版本上。
8. `tools/build/verify_adventure_package.py`：新文件加进必需清单。
9. `plugin.toml`、`pyproject.toml` 的版本号，`README.md`、`docs/module-map.md`，以及一份新的 `docs/adventure/adventure-*.md`。

## 6. 不能破坏的约定

1. **不改宿主。**
2. **表现与规则分开。** `*-art.mjs` 只读战斗状态，不消费战斗随机数、不写快照、不改碰撞体、不做伤害结算。动画用战斗时钟 `scene.elapsed`，不用墙上时钟（顿帧和终结技特写是有意的例外）。
3. **素材缺失要能玩。** 每张贴图载入失败时都回退到代码画的矢量外观。
4. **进快照的东西必须后端校验。** 不想存的短时状态（燃烧、熔岩池、形态计时器）可以只放在内存里，读档后重新开始，但要在文档里写明。
5. **金币只由后端结算。**
6. **有「简化特效」开关**，新特效要尊重它（`battle-art` 的 `reduced`）。
7. **性能预算**：粒子最多 180 个，各种特效池都有上限，新特效用对象池，不要每帧新建对象。
8. **密钥不进文件。** 出图脚本从环境变量 `IMG_KEY` 读密钥。
9. **原创。** 不画原作角色，不直接搬原作招式名；借用的是阶位这类框架。
10. **如实汇报。** 没验证的就说没验证；测试没全过就列出哪几项、为什么。项目主人依赖这些说明来决定下一步。

## 7. 现在的玩法（规则 18）

### 一局的流程

- 九段路程：林缘、苔石遗迹、荆棘深处各两段战斗；前两片以守关强敌（苔甲卫士、荆棘咏者）结束，最后一段是首领林地守望者。
- 每段在一张 1300×900 的小场地里（林间空地、断墙小径交替），目标是「坚守 90 秒」或「清剿指定数量」。
- 清完一段：剩余敌人溃散，结晶自动收回，发放门后奖励，然后选门。门上写明下一段的目标和奖励（研习、休整、灵感）；从第二段起可能多一扇敌人更强、奖励翻倍的「险路」。
- 从第二段起普通敌人有小概率是带词缀的精英（迅捷、坚甲、分裂）；两个守关强敌半血后进入第二阶段，首领有三个阶段，转阶段时都会召来援兵。
- 难度按所在的段计算，不按总时间。
- 金币：战斗段 14、险路另加 7、守关 22、通关 80。
- 地形（规则 16）：苔石遗迹断墙小径里的石柱能被打倒，碎石砸伤附近敌人；荆棘深处有荆棘丛（减速到 55%）和毒雾（每 0.5 秒玩家 −2、不致死，普通敌人 −10）。详见[地形机制](adventure/adventure-terrain-hazards-2026-11-16.md)。
- 停靠点（规则 14）：每片林地第一段战斗后，选门时多一扇停靠门，背后是篝火、行商或奇遇，处理完回到选门。局内货币「林晶」从战斗段获得，只在本局行商处使用。详见[停靠点与林晶](adventure/adventure-journey-stops-2026-11-16.md)。

### 构筑

- 玩家和同行各有自己的技能，升级时轮流研习（每三次有一次归同行）。等级上限 50。
- 玩家最多 3 个自动技能和 2 个手动技能（Q、E）；同行最多 2 个自动技能和 1 个支援技能。
- 普通技能 5 级：2 级选侧重，3 级选分支，5 级觉醒或与另一技能融合。

### 火系（目前唯一做深的流派，作为样板）

**技能线**（自动攻击）：火弹升满 5 级后进阶，每阶的新形态也是 5 级，旧形态保留但间隔加倍。

| 阶位 | 形态 | 节奏 |
| --- | --- | --- |
| 初级 | 火弹 | 高频低伤，单体 |
| 中级（三选一） | 焰刃 / 喷焰 / 爆炎 | 近身扇形 / 持续锥形 / 延迟定点爆炸 |
| 上级（二选一） | 熔流 / 狱炎弹 | 减速灼烧的熔岩 / 缓慢碾压的巨大火球 |
| 圣级 | 瞬燃 | 点燃全场并引爆场上所有的火 |

**连携**：火弹打中熔岩里的敌人喷火柱；爆炎优先炸燃烧中的敌群；狱炎弹碾过燃烧的敌人会变大；瞬燃引爆所有灼烧、熔岩、火区和待爆法阵。

**手动技能线**（规则 13）：焰环升满 5 级后进阶。中级炎墙／大炎球二选一，上级地脉／燃域二选一，圣级炎柱。按一次焰环的键，从焰环起依次放出已学会的全部形态（每段隔 0.3 秒，低阶六成伤害，冷却按最高阶算）；炎柱会让场上每片熔岩、火区和炎墙各喷一根小火柱。详见[手动技能线](adventure/adventure-fire-chain-2026-11-16.md)。

**精通**：天坠（手动技能）5 级后还有三档精通。火弹和焰环的精通已分别被两条技能线取代。

**流派共鸣**：按角色计点（每个火系技能 1 点，5 级再 1 点，每档精通 1 点，每个进阶形态 1 点、升满再 1 点）。2 点引燃，4 点燎原（燃烧的敌人死亡时爆炸并传染），6 点炎心（间隔缩短、终结技充能加快）。

**终结技「炎阳坠」**：击败敌人充能，按 R 施放，先插入立绘特写再全屏落地。

### 剑系（规则 15 起，第二个做深的流派）

迅斩升满 5 级后进阶：中级三选一（瞬光／流返／幻剑，对应迅剑、静水、北辰三流），上级二选一（剑压／千刃），圣级断界。剑击给敌人叠「剑意」，断界和拔刀斩引爆剑意。剑系共鸣三档：破绽、连锋、剑心。终结技由共鸣点数多的一系发动。详见[剑系自动线](adventure/adventure-sword-line-2026-11-16.md)。立绘标准是 `foe-sprite-source\sword\concept-sword-portrait.png`。

**突进手动线**（规则 18）：破阵突进升满 5 级后进阶。中级连斩／回身斩二选一，上级八方斩／残影二选一，圣级剑域。按一次突进键先突进，再每隔 0.26 秒依次放出已学会的形态（低阶六成伤害，冷却按最高阶算），每一刀都叠剑意并计入剑系共鸣。剑域约 2 秒内在阵中瞬移连斩，期间无敌。详见[突进手动线](adventure/adventure-dash-line-2026-11-16.md)。

其余流派（冰、风、岩、雷）还停在 5 级封顶的旧设计。

## 8. 美术

### 风格

日系手绘 Q 版，地图和怪物偏明亮卡通（项目主人要求）。角色和怪物用贴图，特效、打击反馈和地图主要由代码绘制，再叠加少量 AI 绘制的特效图。

火系特效的标准画法：白黄色的芯、橙色的身、深红的边，硬边赛璐璐，形状干净。项目主人确认过的参照图在 `foe-sprite-source\fire\`：

- `standard-portrait-fire-traveller.png`：**火系主角立绘的标准**，游戏里终结技特写用的就是它。
- `story-fire-ultimate.png`：留作剧情图片。
- `concept-fire-tiers.png`、`concept-fire-kit.png`：技能分档和特效套件的画法参照。

主角「旅人」的设定：灰色短发，青绿色旅行外套，酒红围巾，琥珀石木杖。同行使用宿主角色 YUI 的外观。

### 出图流程

**每开一类新素材，先出几张概念图给项目主人确认画风，再出正式素材。** 这是他的明确要求。

1. 用 `foe-sprite-source\gen.py` 调用图像模型。接口地址和模型名在脚本里，密钥从环境变量 `IMG_KEY` 读。项目主人给过的密钥是临时的，需要时向他要。
2. 原图和提示词都存进 `foe-sprite-source\`，方便以后重出。
3. 按用途处理后放进 `static\art\`：

| 用途 | 做法 | 例子 |
| --- | --- | --- |
| 主角、同行 | AI 出一张分件图 → 脚本切件 → `rig.py` 等绑定脚本摆姿势 → 烘焙成帧表。不使用 Live2D 运行时 | `player-traveller.png` |
| 怪物（步骤 0.9.7 起） | AI 在同一张图里画出待机、蓄力、出招、受击四个姿势（透明底或白底），切出后统一缩放，烘焙成 16 格动作表 | `foe-*.png`，源图在 `foe-sprite-source\cartoon\` |
| 地图（步骤 0.9.4 起） | 每片林地一张只有地面的底图，加一张透明底的障碍物素材表，切成五件 | `map-*.png/jpg`，源图在 `foe-sprite-source\maps\` |
| 发光特效 | 纯黑底出图，游戏里用叠加混合，不需要抠图 | `fx-fire-slash.jpg`、`ult-fire-*.jpg` |
| 有暗部的特效 | 按亮度生成透明度，保留暗色部分 | `fx-lava-pool.png` |
| 有黑色主体的特效 | 纯绿底出图再抠像 | `fx-hellfire.png` |

4. 贴图按显示尺寸绘制，碰撞体保持世界坐标里的原大小。

### 已知的美术弱点

步骤 0.9.7 起怪物换成卡通造型，有蓄力、出招、受击、死亡动作（见[怪物卡通化](adventure/adventure-cartoon-foes-2026-11-16.md)），但移动只是原地压扁拉伸，首领转阶段没有专属动作。玩家施法姿势偏弱。喷焰是用小爆炸拼的，比较粗糙。叠加混合的特效在浅色地面上会偏白。所有画面只在软件渲染下看过，真实显卡上的效果没有确认。

## 9. 项目主人已经做的决定

| 事项 | 决定 |
| --- | --- |
| 素材来源 | 混合：特效和地图用代码，角色和怪物用贴图，技能特效可以用 AI 绘图 |
| 画风 | 日系手绘 Q 版 |
| 原作参考方式 | 借体系框架，名称原创；名字要好辨认 |
| 角色素材形式 | 分件绑定，方便做动作 |
| 关卡结构 | 节点制**直接替换**连续生存，一局约 20 分钟 |
| 测试 | 减少等待：平时只跑定向测试，不要每次都跑完整一轮 |
| 旧规则兼容 | 全部保留 |
| 技能深度 | 按阶位进阶；旧形态保留并减频；一局内就能升到最高阶 |
| 元素反应 | 不想要 |
| 喜欢的表现风格 | 国产二次元动作游戏那种大招特写和华丽技能演出 |

他的试玩反馈（按时间）：整体方向认可；段间不回血属实；升级偏快但没满级过；首领偏简单、容易被秒；加了精通后仍觉得单流派偏浅（于是有了技能线）；关卡太简单、几乎一路平推（于是上调了难度，但他**还没反馈上调后的感受**）。

## 10. 没验证的和已知的问题

- **所有数值都是推算的**，没有经过系统的试玩调整。火系现在很可能过强。
- 自动测试靠直接改时间、击败数或直接构造高等级构筑来走流程，验证的是规则和存档，不是手感；没有任何测试是从 1 级真实打到通关的。
- 等级上限提到 50 之后，一局实际能升到多少级没有测过。
- 精英词缀、守关新招式和首领第三阶段刚加入，强度没有经过试玩。
- 规则 17 起，打完一段后在场地边缘亮出出口，走进去选路；暂停时仍可在面板里直接选。
- 0.9.4 起各段按林地换上正式画面；步骤 0.9.5 加了遗迹石柱、深处荆棘和毒雾。步骤 0.9.6 加了走出口选路和首领圣所第三阶段的根须封场。步骤 0.9.8 加了突进手动线（见[突进手动线](adventure/adventure-dash-line-2026-11-16.md)），剑域的无敌和残影的伤害还没试玩。
- 贴图载入失败时的回退路径没有专门的测试。
- 没有在宿主内完整跑过，开发都在独立预览里进行。

## 12. 工作方式

- **版本库**：GitHub 仓库为 `qaqms/n.e.k.o_plugin_love_with_you`，主分支 `main`。2026-11-16 按项目主人明确的提交推送要求，将当前工作目录接入该远程仓库的已有历史。只在得到提交推送指示后推送，不自动发布标签或市场版本。旧的 `-main` 目录和推送脚本约定不代表当前路径。

- 每次改动前，把要覆盖的文件复制到插件内的 `archive/backups/<旧版本>-<主题>-<日期>/`，保留原相对路径并加 `.bak` 后缀，避免被宿主静态扫描当作另一份入口。
- 一次改动对应一个版本号和一份 `docs/adventure/adventure-<主题>-<日期>.md`，写清楚做了什么、数值、存档兼容、没做的、没验证的。项目级整理可记在 `docs/`。同时更新 `README.md` 的对应小节和 `docs/module-map.md`。
- 先写规则和测试，再做表现。纯规则尽量放进不依赖 Phaser 的模块（如 `skills.mjs`、`journey-rules.mjs`），用 Node 直接测。
- 做完后在预览里实际截图看一遍，把截图发给项目主人。
- 大的方向（玩法结构、画风、是否替换已有系统）先给方案让他选，不要直接做。小的实现细节自己决定并说明。
- 汇报时先说结论和他能看到的变化，再说测试结果，最后单独列出没做的和没验证的。
