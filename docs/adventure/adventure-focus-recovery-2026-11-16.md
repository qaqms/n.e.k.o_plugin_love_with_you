# 同行游戏暂停与控制权恢复（0.12.2）

## 反馈与证据

- 用户在 `D:\N.E.K.O_0.0.0-20261103-037b3f1e_win` 导入 0.12.1 后，选完起手招式停在「稍作休息」00:00，「继续」无效。
- 2026-11-16 插件日志显示开局与保存请求执行，原错误日志为空；当前旅程已存入起手技能，但 elapsed 为 0。未发现存档校验失败能够解释最初的暂停现象。
- 普通浏览器的静态主面板嵌套测试原本可以继续。隔离测试模拟子文档 `document.hasFocus()` 持续返回 false 后，原代码稳定停在暂停界面；这是可复现的触发条件，尚未直接证明真实 Electron 窗口的底层焦点异常来源。
- 加强为真实计时断言后，发现隐藏游戏页时 Phaser 自动缩放可能取到 0×0，抛出 `Framebuffer status: Incomplete Attachment` 并停止渲染循环。强制在隐藏页执行真实缩放刷新可稳定复现；修复前定向用例失败。旧测试使用异步 `waitForFunction` 谓词，Promise 本身为真，不能保证计时真的推进；现在改为逐次等待返回数值后比较，并检查界面时钟。
- 用户另报告 `adventure_controlled_elsewhere`，同期日志有对应冒险入口执行失败。后端仅在另一个 client 持有控制权且本次 claim 未显式接管时返回该错误。页面关闭不会自动释放运行中插件内的 owner，因此旧页面也可能留下占用。

## 修改

- 游戏以真实 pointerdown、keydown、click 及窗口 focus 更新前台状态，避免仅凭嵌套文档失效的焦点报告拒绝继续。
- blur、document hidden、侧栏隐藏均暂停，并撤销前台状态；只恢复显示或收到异步保存回执不会自动开战。主面板同步游戏的显示与隐藏状态，iframe 加载后补发当前状态。
- 游戏页聚焦时不再触发关系面板刷新，普通页面仍保留原来的刷新行为。
- 为 Phaser 自适应缩放设置最小 1×1 画布，避免隐藏页创建零尺寸 WebGL 帧缓冲；返回时按真实容器尺寸恢复。
- 控制权错误显示专用恢复页。「接管此旅程」必须确认，再重新读取最新保存的旅程和修订号、发起显式接管；取消确认不会转移控制权。仍可只读取存档。
- 保留后端的单页控制、幂等回执和拒绝旧页写入机制，没有自动接管或持久化复用 client。

## 兼容与验证

战斗规则仍为 12，存档版本仍为 13；不改快照、数值、金币或宿主。修复从最新已保存位置恢复，不保证恢复已关闭页面里未保存的进度。

定向回归覆盖真实静态主面板及嵌套游戏：桌面与窄屏开局、切页暂停、隐藏时真实缩放刷新、返回继续、计时推进、键盘移动、上下文刷新保留页面、焦点报告失效、旧 client 占用时取消及确认接管并再次保存；纯协议测试覆盖宿主包装后的错误码提取。发布前另跑后端、纯规则和相关独立游戏浏览器回归，并校验构建包与源码一致。
