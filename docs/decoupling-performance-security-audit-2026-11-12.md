# 0.7.3 解耦、性能与安全审查

日期：2026-11-12。基线：0.7.2。本轮只修改插件，不新增玩法，不修改宿主代码，不安装、重载或替换运行中的插件，不修改实际存档。

## 结论与范围

本轮改善面板生成、事务快照和素材检查的成本，并修复本机传输、数据解析、停止边界与评分超时中的具体问题。既有关系规则、金币额度、角色隔离、界面数据结构和交互流程保持兼容。

审查覆盖面板数据生成、状态事务、存档读写、本机 HTTP、立绘与外观操作、评分提示和模型请求。原有 0.7.2 的迁移、隔离备份、消息提交和重试修订继续保留，见 `stability-audit-2026-11-12.md`。

## 解耦与性能

| 修改 | 原因与边界 |
| --- | --- |
| 新增 `_dashboard.py` | 不依赖 SDK、网络或文件系统。在主锁内生成脱离原状态的快照，锁外计算关系展示、趋势与纪念日；只复制当前模式展示的关系，每份只复制需要显示的最近 20 条历史，不复制交易回执等隐藏数据 |
| 缩小事务备份范围 | `_state_transaction_locked(*namespaces)` 可指定顶层状态域。金币进度只备份 `shop`，共同经历操作只备份 `experiences`，角色同步只备份角色列表与当前角色；异常恢复对应原状态。未指定时保留整体回滚，跨域赠送仍保护关系、库存、余额与回执的一致性 |
| 素材操作独立锁 | 立绘与外观共用 `_asset_call()`，统一处理启停代次、错误和操作准入；文件操作使用素材锁，不占用关系主锁。停止流程等待已经接纳的素材操作完成，再完成停止切换 |
| 减少重复文件检查 | 固定立绘选择在一次调用中复用可用性检查结果。没有增加长期缓存，文件删除或替换仍可被下次调用观察到 |
| 评分数据只保留一份 | 删除重复拼接的角色和对话正文，只保留结构化 JSON 数据块及原有判断规则。同一份最大长度合成样例，提示由 3308 字符降至 2042 字符；未测量真实模型 token、费用或评分质量变化 |

独立关系模式仍需生成每个角色的趋势和纪念日，耗时降低幅度小于共用模式。保存仍对完整存档进行序列化和原子替换；本轮没有改变文件格式或把完整写盘替换成增量写盘。

## 已复现并修复的边界问题

| 问题 | 修复与验证 |
| --- | --- |
| 本机请求自动跟随重定向 | 原 HTTP 客户端会继续请求重定向地址。新增禁止重定向处理器，保留代理绕过；本机测试覆盖 301、302、303、307、308，不访问外部地址 |
| HTTP JSON 正文缺少默认总量限制 | 统一默认最多 8 MiB，已有更小调用限制继续生效；超过上限拒绝解析，不返回截断成功结果 |
| 存档读取无统一体积边界 | 默认上限 32 MiB，先检查文件大小，再有界读取，避免检查后文件增长造成无界读取；构造存储对象时可指定测试用上限 |
| JSON 接受歧义或异常数值 | 新增 `_json.py`，磁盘和本机传输统一拒绝重复对象键、`NaN`、`Infinity`、浮点溢出及超过 64 层的容器嵌套；捕获解析递归错误 |
| 异常数据写入覆盖原文件 | 写盘前验证非有限数值、大小和嵌套深度，失败时不替换原文件；继续使用临时文件、刷新与原子替换。保存异常转换为插件错误，使事务恢复内存状态 |
| 停用后部分面板动作仍可写盘 | 补齐关系修改、称呼、日期、设置、纪念日和模式切换的就绪检查；模式切换的异步角色同步完成后再次核验启停代次 |
| 素材操作与停止相互穿插 | 操作统一核验启停代次，停止后不再调用素材服务；停止等待已经接纳的素材操作排空。测试验证素材 I/O 不持有关系主锁 |
| 可选旧版插画消失或在读取时增长 | 元信息检查容忍文件删除和空文件；正文按原有 1 MiB 限制有界读取并核对实际长度，避免可选素材破坏整个面板 |
| 评分超时不包含获取模型客户端 | 将 30 秒超时覆盖到完整请求，包括获取客户端和生成；测试分别验证两阶段超时及外部取消传播 |

非法、超大或过深的现有存档会按既有机制隔离，保留原始字节并停止启动，不以默认钱包或关系覆盖。未来版本号等不支持格式继续按 0.7.2 的规则保留原文件并拒绝启动。恢复应先保留隔离副本，从可信备份恢复数据后再重启；不要直接删除异常文件来让插件生成新数据。

评分提示把动态角色信息与对话放在 JSON 数据区，减少正文混入指令的机会；这不保证消除模型提示注入，也不证明聊天模型会遵循所有规则。

## 合成性能测量

工具：`tools/benchmark_stability.py`。基线从本地 0.7.2 导入包提取 Python 源码，当前版使用本目录源码；两者使用同一隔离 SDK 测试环境、临时目录与合成数据，不读取已安装插件或实际存档。

每组含 16 或 64 个角色，每角色 50 条历史、400 个日值及 10 条共同经历便签。每项执行 9 次，记录耗时中位数；另执行一次，用 `tracemalloc` 测量 Python 分配的峰值，不是进程总内存。前后测量顺序执行，没有同时运行界面回归。

| 16 角色，独立关系，面板生成 | 15.153 | 14.329 | 661.5 / 480.7 |
| 64 角色，共用关系，面板生成 | 33.265 | 4.787 | 2133.0 / 274.0 |

只测事务备份的结果用于解释复制成本，不能代表一次完整保存。包含原子写盘的结果才包含对应合成进度更新的保存开销。固定立绘选择减少检查耗时，峰值内存基本不变。以上是本机合成样本，不是整套宿主的 CPU、常驻内存、真实玩家延迟或模型响应时间。

复现命令（在插件根目录，使用宿主已有 Python）：

```powershell

& '../N.E.K.O/.venv/Scripts/python.exe' -B tools/benchmark_stability.py --output .benchmarks/stability-after.json
```

原始结果保存在本地 `.benchmarks/stability-before.json` 和 `.benchmarks/stability-after.json`，开发工具、测试与基准结果不进入导入包。

本轮不保证没有剩余缺陷。聊天模型对提示的遵循、实际模型耗时、导入升级后的日常聊天与素材操作仍需实机验证；测试通过和合成基准不能替代这些验收。
