# 礼物商店

## 使用

进入「礼物商店」购买商品，在「背包」选择送礼对象，确认礼物和本次好感变化后送出。「赠送记录」保留最近 50 次赠送和回应状态；实际回复在宿主聊天中。「收支记录」保留最近 100 笔奖励和购买。

首次启用获得 100 币。每天正常合格互动达到第 1、3、8 轮，分别自动到账 10 币；本周四个自然日各达到三轮合格互动，再获得 40 币，不要求连续。周按本地星期一至星期日计算，一周常规收入最多 250 币。余额、背包与收入进度由所有角色共用。每种礼物最多持有 99 份。无充值、兑换现金或外部购买。

收入计数不依赖评分、模型或面板打开状态。正常的用户消息和对应回复形成一轮，多条连发合并算一轮；间隔至少 20 秒，当天规范化后相同的用户发言只计一次。主动消息和礼物回应不计数；不补算停用期间旧消息。消息正文只在内存，有限指纹、奖励档位和周资格持久化。

| --- | --- | --- |
| 暖心红茶 | 20 | 1 |
| 草莓蛋糕 | 40 | 2 |
| 手作巧克力 | 40 | 2 |
| 当季花束 | 60 | 3 |
| 精装故事集 | 60 | 3 |
| 柔软玩偶 | 80 | 4 |

送礼每天最多增加 4 点，所有角色与关系模式共用送礼额度。聊天每天每份关系最多 +4，两种来源分开，单份关系正向总上限 +8、负向上限 -4。扣分不返还正向额度，切换模式合并已用额度而不重置。实际加分取商品加分、全局送礼剩余、关系每日剩余与距 100 分差值的最小值。

普通赠送没有加分空间时不消耗礼物；明确选择「仅表达心意」可零加分消费一件礼物并请求回应，全角色每天限一次。共用模式仍向指定角色送礼，但数值计入共用关系。告白门槛继续生效。

## 保存和重试

- `_shop.py` 保存商品规则、经济状态归一化、交易校验与展示投影；它不依赖 SDK。
- `state.json` 的 `shop` 命名空间增加经济规则版本 2、日周进度、日期最高值、有限去重指纹、累计收入、收支流水与零加分赠送日期；关系记录增加聊天、礼物来源额度和好感修订。整体关系 schema 仍兼容 v3。
- 升级前备份旧商店存档到 `state.pre-economy-v2.json`。余额、库存和好感不变；旧签到当天不叠加新日奖励，旧加分来源无法确认时当日暂停新正向结算，次日恢复。迁移只执行一次。
- `buy_shop_item`、`send_shop_gift` 要求 `request_id` 与 `revision`。相同请求重放原结果；参数不一致拒绝；旧版本拒绝。送礼还必须提交 `expected_gain`、`relationship_revision`，并可显式设置 `gesture=true`。关系或实际加分变化时不消费，要求重新确认。
- `claim_shop_coins` 保留为旧请求的回放入口，不接受新的手动领币；旧回执语义不变。
- 同一把状态锁及原子文件替换涵盖库存、余额、好感和回执。保存失败回滚内存，不发出角色回应。
- UI 在结果不确定时保留原请求，阻止新的商店交易，提供「确认上次操作」。已确认保存但刷新失败时只刷新显示。
- 收入进度、来源额度和赠送次数按本地日期计算，日期倒退不重开额度。午夜前用户发言、次日收到正常回复的轮次归原用户日期；只保留当前与前一日账及两周资格。一天以上的迟到轮次忽略。
- 自动收入的计数、指纹与奖励原子保存；保存失败进入只含指纹的有限内存队列，下次维护重试。进程退出且宿主无法重取的轮次不保证补算。存档损坏会隔离并停止启动；即使下次状态文件缺失，也要求先恢复隔离的存档。

## 角色回应

先提交礼物交易，再通过宿主 `push_message(visibility=[], ai_behavior="respond")` 请求目标角色回应。提示包含商品、关系阶段、称呼及最近赠送次数，使用宿主聊天模型，不使用好感判断模型。提示要求不另行结算好感、不跳过告白、不复述内部编号。

请求之前保存尝试次数和不确定状态。重启不自动重发；提交成功只意味着本地请求已接收。若收到明确关联的回复，更新为 `received`。宿主离线文本通道的 `proactive_instruction` / `proactive_reply` 共用 `conversation_id`：插件在内存中把包含礼物编号的指令与后续回复关联。兼容带完整事件元数据的回复。缺少关联信息时保留不确定状态，不凭时间邻近或感谢关键词猜测送达。

送礼回应属于主动回复，不进入普通对话自动评分或金币进度。赠送时使旧评分任务失效，避免并发的旧判断影响本次结算。金币配对器与评分配对器独立，切换评分或送礼不清空正常相伴进度。正文不写入本地商店状态。

`retry_gift_reaction` 仅重新请求回应，绝不再扣礼物或增加好感。每笔赠送共最多请求三次；失败后等待至少 30 秒，已提交未确认时等待 120 秒。重试提示明确说明是同一份礼物。不能保证宿主已播放后的重试不产生第二句回复，所以 UI 不会自动重试。

## 验证

Python 回归包含迁移、保存失败回滚、重复与并发请求、日期边界、价格和库存校验、实际加分裁剪、告白门槛、独立角色、评分失效、回应失败与宿主会话关联。

浏览器测试使用宿主真实 TSX 渲染器和控件配合模拟业务数据，覆盖购买与送礼、丢失响应后的原请求确认、刷新失败、回应重试、多语言和深浅主题布局。另在与 Hosted UI 相同的 `sandbox="allow-scripts"` iframe 内验证购买流程。未启动宿主或调用实际聊天模型；实际模型反馈需要在宿主中联调。
