# 抚摸模式里的 3D 手：方案（待项目主人选择）

项目主人的想法：「摸摸她」模式下加一只 3D 的手，方便控制和抚摸；以后不只是点一下头，而是能用手和 Yui 有更多接触，比如左右摸头。

按约定，新一类美术素材先出概念图，确认后再做正式素材。

## 1. 手从哪里来

| 方案 | 说明 | 优点 | 问题 |
| --- | --- | --- | --- |
| **A. 用代码搭一只卡通手**（概念图就是这个） | 手掌、手指、袖口由圆角块和胶囊拼成，卡通着色，颜色和 Yui 一致 | 完全原创，没有授权问题；几乎不增加包体；手指每节都能单独弯曲，换姿势、做动画都简单 | 造型偏简单、圆润，细节比不上专门建模 |
| B. 用 Meta 提供给 WebXR 的通用手模型（`generic-hand`） | glTF 格式，25 个关节，MIT 授权 | 骨骼完整，比例真实 | 写实风格，和 Yui 的二次元画风不搭，要重新上色；需要从网上下载（要你同意），发布时附 MIT 授权说明 |
| C. 在 Blender 里建一只正式的手 | 用现有的 Yui 导出流程导出 | 造型最好，可以和 Yui 的手同一个风格 | 工作量最大；仍要先出概念图 |

另外查到 OpenGameArt 上有一套 CC0 的低多边形手臂（第一人称游戏那种，带整条胳膊，只有 FBX），以及 CGTrader 上的一些卡通手，基本是付费或非 CC0 授权，不建议用。

**建议 A**：先用代码手把交互做出来、调顺手感；以后如果觉得造型不够好，再按 C 换成正式模型，交互代码不用改。

## 2. 做概念图时发现的一点

镜头在 Yui 正前方，如果手从镜头这边伸过去，袖口会正对镜头，把手和她的头都挡住（第一版概念图就是这样）。所以手要**从侧面伸过来**，袖口留短。很多同类游戏的手也是从画面侧边进来的。

## 3. 有了手以后怎么摸（建议下一版做）

- **手就是鼠标指针**：进入「摸摸她」，鼠标变成这只 3D 手，跟着鼠标移动，悬在她身上方一点。移到不同部位时自动换姿势：头上手掌朝下，脸上伸出食指，手上手心朝上，耳朵和尾巴用指尖轻碰。
- **按住就是摸，拖动就是抚摸**：按住后手贴上去；在头上左右拖，手跟着来回抚摸，她的头会随手的方向轻轻偏一下，耳朵被压下又弹起。
- **计算摸了几下**：松手时把「摸了多久」和「来回摸了几下」一起发给桌宠（现在只发时长，要加一个次数档位，后端校验和测试同步改）。
- **触屏**：手出现在手指按下的位置；**键盘**：用卡片上的按钮，手自己做一次摸头动作。
- **减少动态效果时**：手直接出现在部位上，不做来回动画。
- 反应档位、等反应做完才能摸下一次、每次都告诉桌宠，这些规则都不变。

不做：手和头发的精确贴合（她的头发是硬的模型，只有双马尾会动，手放上去不会压出凹陷）。

## 4. 需要你决定的

1. **手用哪个方案？**（建议 A）
2. **要不要袖口？** 袖口能让人看出这是「你的手」，也能遮住手腕的截断处。颜色用概念图里的灰蓝，还是别的颜色，或者干脆不要袖口？
3. **「来回摸了几下」要不要告诉桌宠？** 告诉的话，桌宠可以说「摸了好多下」之类的话；不告诉，就和现在一样只按时长。

## 5. 这一版顺带修的：推近后过曝

推近 Yui 时人物过亮，原因是给「推近看物件」准备的补光也加到了 Yui 身上：黄昏和夜里看便签、日历时会把主光调亮，最多到 6 倍左右；她本身还带一部分自发光，旁边又有台灯，叠在一起就过曝了。现在 Yui 的近景不再加这份补光；黄昏的低角度阳光直接照在她正面，所以黄昏时她的自发光也减一些，镜头靠近她时这束阳光也调弱一些。白天和夜里不受这两项影响。前后对比在 `archive/reviews/cottage/yui-closeup-{dusk,night}-{before,after}.png`。

## 6. 决定（2026-11-22）

项目主人：「工作量不大效果好的就行了，袖口灰蓝色就行了」。所以用方案 A，袖口灰蓝色。第 3 条（来回摸了几下要不要告诉桌宠）没有回答，0.9.37 先不发次数，后端不变。已在 0.9.37 实现，见 `docs/adventure/adventure-cottage-yui-2026-11-21.md`。

之后项目主人看了第一版说「有点假」，指手的建模太简陋。于是改成介于 A 和 C 之间：仍然完全由脚本生成、不用外部素材，但在 Blender 里用变形球融合出一整块平滑的手，带骨骼（`tools/assets/build_hand.py` → `static/models/hand.glb`），袖口保持原来的短袖口。
