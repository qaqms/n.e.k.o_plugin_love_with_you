# 和 3D Yui 互动：方案（待项目主人选择）

项目主人的想法：点击小屋里的 Yui，镜头推近，浮现几个选项（抚摸、送礼……）；3D 的 Yui 负责动作和表情，桌面桌宠负责说话——比如摸了 3D Yui 的头，桌宠按好感度回一句「好舒服」或「别摸我的头」。

## 1. 现在已经有的

| 已有 | 位置 | 可以怎么用 |
| --- | --- | --- |
| 面板立绘的「抚摸」：头、肚子、腿三个部位，按关系阶段给桌宠发一条提示，桌宠回一到两句 | `touch_portrait` 入口、`prompts.portrait_touch_prompt`，冷却 8 秒 | 3D 抚摸直接沿用这条路，只换提示文字和部位 |
| 提示里已有分阶段语气，并写明「可以礼貌表达边界，亲密关系也不表示默认同意」 | `prompts.STAGE_TONES` | 「好舒服」和「不想你摸我的头」就是这样来的，不用另写规则 |
| 送礼：买礼物、送出、扣库存、加好感、桌宠回应、失败可重试 | `send_shop_gift`、`retry_gift_reaction` | 3D 里送礼只是换个入口，结算不动 |
| 小屋邀请聊天（沙发上的杯子） | `invite_cottage_chat` | 「和她说说话」可以沿用 |
| 3D Yui 的视线、表情、手势、害羞、按关系阶段的神情 | `static/cottage-yui.mjs` | 互动时的本地反应 |

所以这一版主要是**小屋前端的新交互 + 一个新的后端入口（3D 抚摸）+ 几条提示文字**，不需要新的结算逻辑。

## 2. 同类游戏的做法（参考）

- **碧蓝航线、蔚蓝档案、赛马娘**的主界面/宿舍：点角色不同部位有不同台词，好感度高了解锁更亲近的反应，好感低时会嫌弃或躲开。我们的「按阶段换语气」就是这一套。
- **LovePlus** 的触摸模式：镜头推近，可以摸头、戳脸、牵手；摸得太多或摸错地方，对方会不高兴。重点是**反应要立刻出现在角色身上**，文字只是补充。
- **VPet / 各种桌宠**：摸头是最常用的互动，反馈要即时、频繁也不烦——所以**本地动作每次都给，说话要节制**。
- **《米塔》**：互动选项很少，但每个都有完整的表演（看你、靠近、表情变化），比选项多更有效。

我们能借的三条：

1. **身体先反应，桌宠再说话**。摸头的瞬间 3D Yui 就闭眼、耳朵压下、笑或者躲开；桌宠的话一两秒后才到。
2. **一段抚摸只说一次话**。连续摸 3 秒算一次「摸了好一会儿」，停手后才发给桌宠，避免刷屏和触发冷却。
3. **距离感随关系变化**。陌生时她会侧身躲开手；恋人阶段会把头靠过来。这比文字更能体现好感度。

## 3. 建议的互动（按优先级）

### 第一批（建议 0.9.36 做）

**点击 Yui → 镜头推近 → 她身旁浮出几个选项**，样式沿用小屋的纸页卡片，Esc 或「返回」退回原视角。

| 选项 | 3D 里发生什么 | 桌宠 |
| --- | --- | --- |
| **摸摸头** | 进入抚摸模式：鼠标变成手，在她头上来回划。她按关系阶段反应：陌生时侧身躲开、眉头皱；熟悉时不太自在地笑；好感以上眯眼、耳朵压下、尾巴摆快；恋人时把头靠过来 | 停手后发一次，带上摸了多久 |
| **戳戳脸** | 她鼓一下脸、瞪你，或者害羞地笑 | 同上 |
| **牵手** | 她看看你的手，按阶段决定要不要把手伸过来 | 同上 |
| **猫耳朵 / 尾巴** | 耳朵一抖、尾巴一甩；猫娘对尾巴比较敏感，低阶段会明显不乐意 | 同上 |
| **送礼物** | 弹出背包里已有的礼物，选一个送出；她做「开心」手势 | 沿用现有送礼回应 |
| **和她说说话** | 她看着你，等桌宠接话 | 沿用小屋邀请聊天 |

只开放头、脸、手、耳朵、尾巴，**不做胸、腿、裙子这些部位**：一是内容尺度，二是这些部位最容易穿模，做出来效果也不好。

### 第二批（之后）

- **她在听 / 在说**：桌宠回话的时候，3D Yui 看着你、嘴巴随说话轻微开合。需要先确认插件能不能知道桌宠什么时候在说话（送礼回应已经能对上回合，可能可以复用）。
- **一起听唱片**：唱机播放时她随节奏轻轻摇晃。
- **合影**：选一个姿势，把画面保存进「共同经历」。会写存档，需要后端校验和测试。
- **早安 / 晚安**：按时段的问候动作，桌宠配一句。

### 不建议现在做

- 换装、喂食道具拿在手上：要新的美术素材，按约定要先出概念图。
- 让她跟着你走、坐到沙发上：属于方向 C，裙子穿模和走路动作都还没解决。

## 4. 需要你决定的

1. **第一批做哪些？**（建议：摸头、戳脸、牵手、耳朵尾巴、送礼、说说话全做，抚摸是重点）
2. **当前桌宠不是 Yui 时怎么办？** 3D 模型永远是 Yui，但桌面上可能是别的角色。
   - A：只有当前角色是 Yui 时才发给桌宠，其他角色时 3D 反应照常、桌宠不说话（建议）
   - B：不管是谁都发，提示里说「用户在小屋里摸了 Yui 的头」，让当前角色自己接话
   - C：把 3D 模型当成当前陪伴角色，不区分名字
3. **抚摸要不要加好感？** 建议**不加**：现在的立绘抚摸也不加，否则容易被反复刷。好感照旧来自聊天和送礼。
4. **桌宠该不该承认自己「在小屋里」？** 现在的小屋邀请提示写的是「不要声称自己出现在 3D 小屋里」。有了 3D Yui 以后，可以改成「用户在小屋里摸了你的头」，让桌宠把 3D 的她当成自己（建议在第 2 题选 A 时这样改）。
5. **说话频率**：建议一段抚摸只发一次，两次之间至少 8 秒（沿用现有冷却）；这期间 3D 反应照常。

## 5. 实现要点（给开发参考）

- 新后端入口 `touch_cottage_yui`：参数是部位（头、脸、手、耳朵、尾巴）和时长档位（轻碰 / 一会儿 / 很久），严格校验；新提示 `cottage_touch_prompt`；沿用请求编号去重、冷却和「当前角色是否一致」检查。不写存档。后端测试同步加。
- 小屋前端：新的近景镜头 `yui`、选项卡片、抚摸模式（在头、脸、手、耳朵、尾巴的骨骼上挂不可见的命中球，鼠标划过时判定部位和时长）、按阶段的本地反应（复用现有表情和姿势层，再加几个程序动作：侧身躲、靠过来、伸手）。
- 送礼和说话都走现有入口。
- 减少动态效果和低画质时：镜头直接切换，反应用表情不用大动作。

## 6. 项目主人的决定（2026-11-22）

1. 第一批全做。
2. 不区分当前桌宠是谁，都按 Yui 处理，暂不处理这个问题。
3. 抚摸不加好感；以后重新设计好感度系统。
4. 让桌宠知道自己在小屋里，但不需要强调说出来（以后小屋里可能有更多互动）。
5. 每次互动都让桌宠知道，两次之间没有说话间隔；但必须等动作完整做完才能进行下一次抚摸。
