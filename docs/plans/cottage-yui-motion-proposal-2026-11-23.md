# Yui 的穿模、动作流畅度和过渡：方案（2026-11-23）

项目主人反馈：

- Yui 穿模还是比较严重，身体和衣服互相穿；
- 动作不太流畅；
- 起床、被叫醒下床、做事时被点击转为和你互动，这些过渡很不自然：位置是直接平移过去的，没有真实的动作支撑。

这一份是调查结果和可选做法，**还没改代码**。

## 现在看到的问题

截图在 `archive/reviews/yui-clipping-2026-11-23/`。拍法：用显卡、高画质，把小屋时钟拨到她在各个位置的时刻，用「看看她」镜头每个位置连拍三张。

| 位置 | 看到的 |
| --- | --- |
| 沙发 | 屁股陷进坐垫，右手肘插进坐垫里，整个人往一边歪 |
| 门廊长椅 | 右边袖子陷进椅面，屁股略低于椅面 |
| 书桌 | 坐得太靠前，大腿和肚子穿进桌子前沿；头低得看不到脸；双马尾压进椅背 |
| 料理台 | 背对镜头，手里没有平板（动作本身是拿平板，但场景里没有平板） |
| 地毯站着 | 基本正常 |
| 床 | 被子盖着，这次没看出明显问题 |

原因分四类：

1. **动作是给别的身材做的**。宿主的动作库按另一个模型录制，直接把每根骨头的转动套到 Yui 身上。Yui 的身材比例不一样（0.9.48 起头又放大到 1.1 倍），开衫袖子也很宽，所以手臂容易收进身体和衣服里。脚踩地已经有校正，**坐下没有**：「坐」的动作按录制时的椅子高度坐，小屋里沙发、长椅、书桌椅各高各的，所以有的陷进去、有的离太远。
2. **衣服只有裙摆和双马尾在动**。它们用的是弹簧骨骼，挡住它们的只有腿、躯干上段和上臂这几个胶囊；手和小臂、椅背、家具都不在里面。开衫本身跟着骨骼蒙皮，手臂往里收得多了就会和身体互相穿。
3. **过渡是「平移 + 交叉淡化」拼出来的**。
   - 坐下和起身：1.15 秒内把她从站的位置直线滑到座位上，同时把站姿和坐姿两段动作淡化混在一起。中间没有「屁股往后找椅子、弯膝」的过程，看起来就是飘过去的。
   - 原地转身：只转朝向，脚不动，像在滑冰。
   - 下床：用「从低姿态撑起身体」这段动作分三截正放或倒放，位置由代码按时间从床中间拖到床沿、再拖到地上，和动作对不上。
   - 点击打断：坐着就先「起身」（上面那种滑动），睡着就整套下床，然后才转向你。
4. **可能的卡顿来源（待验证）**：弹簧骨骼固定按每秒 60 步算，不插值。显示器高于 60 Hz 时，身体每帧都在动，裙摆和头发却隔帧才动，看起来会一顿一顿的。走路时移动速度固定（0.6 米/秒），和走路动作的步幅不一定对得上，可能脚底打滑。

## 宿主动作库里有什么

宿主 `static/vrm/` 下共 76 段动作，**没有**坐下、起身、原地转身、下床这类过渡动作。和这次相关、还没用上的有：

- 坐着的互动：坐着开心地大笑、坐着双手平稳细致解释、坐着双手连续大幅交谈、坐着连续拍手鼓掌；
- 站着的反应：惊讶地向后缩起身体、害羞地把双手背在身后、致意问候、自然地举起一只手挥手；
- 别的姿势：休闲地盘着腿坐、侧着身子慵懒地躺下、嚣张地斜靠着半躺。

它们和现在用的几段同属宿主的动作库，许可按宿主的清单走（Apache-2.0，来源 VSWQH，见 `static/models/motion/README.md`）。

## 可选做法

### 一、穿模（建议都做，不需要新素材）

1. **按座位校准坐姿**：每个座位记下坐面高度和前后位置，坐着时把她的臀部放到坐面上（床已经这样做了），书桌往后挪到大腿不进桌子。
2. **手不进家具**：坐着时检查手和小臂，碰到坐面、桌面就用两段骨骼的 IK 往上抬一点（只改手臂，不改动作的其他部分）。
3. **衣服和身体**：
   - 上臂贴身贴得太近时往外推一点，让袖子不吃进身体；
   - 手和小臂加进裙摆的碰撞体，坐着时裙摆更多地跟着大腿，盖在腿上；
   - 双马尾加上肩、背的碰撞体，有椅背的座位再加一个椅背平面。
4. **书桌姿势**：打字时把头和上身抬起一点，能看到脸；料理台给她手里放一块平板（新物件，按规矩先给你看样子）。

### 二、流畅度（建议先量再改）

5. 先在高刷新率下录屏或逐帧对比，确认裙摆和头发是不是在一顿一顿地动；是的话，弹簧骨骼按两步之间插值显示。
6. 走路速度按走路动作的实际步幅算，脚不打滑；原地转身超过一定角度时加小碎步（程序化的抬脚、落脚，不需要新动作）。

### 三、过渡（这部分方向要你选）

- **A. 就地互动（推荐先做）**：不为了互动硬站起来。
  - 坐着时被点：她转头、上身转向你，接着做一段坐着的反应（坐着笑、坐着说话），之后接着做手上的事。
  - 睡着时被叫醒：翻身、在床上撑起来坐着，揉眼或打哈欠，就坐在床上和你说话，不下床。
  - 站着时被点：先做一个惊讶或打招呼的小动作再转向你，代替现在直接转过来。
  - 优点：用宿主现成的动作，没有「滑过去」的那一段，最快见效。缺点：坐下、起身、下床本身（她按作息自己走动时）还是现在的样子。
- **B. 程序化过渡**：坐下和起身改成「脚踩住不动，臀部沿曲线往后下方移动，膝盖随之弯曲」，下床改成按动作里臀部的真实运动推算位置，而不是按时间平移。
  - 优点：不要新素材，坐下和起身不再是飘的。缺点：效果上限不如真实动作捕捉，调起来花时间。
- **C. 补真实的过渡动作素材**：坐下、起身、转身、下床各录或找一段。
  - 来源一：在 Blender 里手调关键帧。这台机器没装 Blender，而且手调质量取决于手艺。
  - 来源二：找授权合适的动作库，比如 Mixamo。它允许用在作品里，但不允许单独分发动作文件；插件发布包里带 `.vrma` 算不算单独分发需要先确认，有风险。
  - 优点：最自然。缺点：素材和许可都没着落。

建议顺序：一（穿模）→ A（就地互动）→ 二（流畅度）→ 视效果决定要不要 B 或 C。

## 怎么验证

用这次的截图脚本，用显卡跑，每个位置连拍（几十秒）；过渡用固定时钟逐帧截图，对比改前改后。不跑整套小屋测试，只挑「Yui's motion keeps her feet on the floor」和打断、叫醒相关的一两项。
