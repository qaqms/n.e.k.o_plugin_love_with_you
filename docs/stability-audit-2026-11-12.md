# 0.7.2 稳定性审查

日期：2026-11-12。基线：0.7.1。本轮只修改插件，不修改宿主，不新增玩法，也不安装、重载或替换正在使用的插件。

## 范围

- 关系与经济存档、角色隔离、好感与金币交易的原子性和重试。
- 聊天来源、工具绑定、请求提交与实际完成的区别。
- 启动、停止、重启、旧版迁移、保存失败和消息提交失败。
- 共同经历草稿、一次性关心提示和用户确认边界。

## 已复现并修复

| 问题 | 原行为与影响 | 处理 |
| --- | --- | --- |
| 草稿标题丢失 | 面板发送标题和正文，`draft_note` 只保存正文 | 同时验证和保存标题；模型仅提供正文时保留标题 |
| 隔离备份覆盖 | 备份名只有秒级时间，同一秒的第二份损坏文件替换第一份 | 在时间后添加唯一标识，各次备份分别保留 |
| 未知存档版本被改写 | 将未来的关系或经济格式当旧数据迁移，规范化时丢弃未知字段 | 启动前检查版本和类型，拒绝未知格式且保持原文件 |
| 结构损坏变成新数据 | JSON `null` 被当作新安装，损坏的角色表或角色记录被默认值替换 | 现有文件与缺失文件分开判断，损坏结构停止启动，不生成新钱包或角色记录 |
| 关心提示重复发送窗口 | 先提交队列，再保存发送标记；提交后崩溃或保存失败，重启可能再发 | 提交前原子保存一次性标记；明确拒收才撤销标记，结果不明不自动重发 |
| 停止后的迟到工作 | 角色查询等异步读取在停止后返回，维护流程仍写盘、发上下文或注册工具；状态查询也会写活跃日期 | 增加启停代次与就绪检查，异步结果应用前核验，在停止边界拦截发送、注册和查询写入 |
| 无明确回执却显示已提交 | `None` 或缺失字段也被视作便签邀请、关系提示提交成功 | 只有布尔值 `submitted=true` 确认提交，其他不确定返回不冒充成功 |

修复用例先在 0.7.1 上运行并失败，再验证修复。恢复测试只使用临时目录，消息接口使用隔离替身，不改用户实际存档。

关心提示沿用现有布尔标记，不升级存档格式。该标记现在表示已安排一次发送，界面八种语言同步使用保守文案。提交前退出可能少提示一次；修改或延后可由用户重新安排。没有宿主的事务式消费回执，无法同时保证绝不重复和绝不遗漏。

## 审阅中未确认的新缺陷

- 金币领取、购买、赠送的余额、背包、好感、回执同一事务保存；重复请求和并发写入已有回归覆盖。本轮未确认新的重复发币或重复扣库存问题。
- 共用与独立关系切换、过期关系工具、角色专属经历和关系重新开始已有隔离与版本校验覆盖。本轮不重写规则。
- 读取宿主普通聊天发布、主动消息发布和 SDK 推送源码，确认提交只代表本地队列接收。不能据此声称模型已读取、已回复或已播放。
- 普通总线与兼容历史解析的来源信息不完全相同；没有证据表明当前宿主将特殊来源按同样字段发布，因此未增加凭猜测的来源白名单。

## 只读实机核对与边界

实机插件服务 `127.0.0.1:48916` 的 `/plugin/status?plugin_id=love_with_you` 与 `/plugins/love_with_you` 返回正在运行的 0.7.1。主服务 `127.0.0.1:48911/api/tools` 显示当前角色已注册 `love_state` 和 `love_address`。这只能证明现有安装与工具注册状态，不能证明本轮 0.7.2 已在实机加载。

没有向真实角色发消息、送礼或启动共创，也没有替换真实存档进行故障注入。聊天模型对关系提示的遵循、自然告白、送礼回应关联，以及旧版宿主兼容路径仍需导入新版后的实机验收。合成预览和隔离测试不等于这些实机流程已经通过。

本轮收口条件为修复上述缺陷、回归通过并交付导入包。后续先体验一次正常升级和日常聊天，再以一个完整的事件玩法为下一轮开发单位，避免同时扩张多个未验证系统。
